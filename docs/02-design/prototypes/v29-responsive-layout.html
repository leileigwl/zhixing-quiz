Taro H5 下的实现方式（不影响 weapp 构建）

  1. 纯样式改动用 CSS 媒体查询，写在各页 index.scss 末尾，并用 Taro 样式条件编译注释包住：/* #ifdef h5 */ @media (min-width: 768px) { … } /* #endif */（app.scss 已在用这种写法），weapp 编译时整段剔除，小程序样式零变化。
  2. 尺寸单位：H5 现按 designWidth: 750 转 rem，且 app.scss 里 html { font-size: clamp(16Px, 5.3333vw, 22Px) } 让根字号在宽屏封顶 22px——卡片内部字号、圆角在宽屏保持手机尺寸，这正是想要的。新增的栏宽、侧栏宽度、最大宽度、间距用大写 Px（pxtransform 不转换）写死，如 max-width: 1120Px、width: 232Px。媒体查询条件里的 px 按 pxtransform 默认（mediaQuery: false）不转换，实现时以构建产物核对一次。
  3. 结构性改动用宽度 hook：useViewportTier() 返回 'mobile' | 'tablet' | 'wide'，H5 下用 window.matchMedia('(min-width: 768px)') 与 (min-width: 1100px) 监听；weapp 下直接返回 'mobile'（process.env.TARO_ENV !== 'h5' 分支编译期裁剪）。只用于 CSS 做不到的事：Dock ↔ 侧栏切换、对话框焦点管理与 Esc、答题键盘监听、曲线 Canvas 重绘。
  4. 导航：custom-tab-bar/ 只服务 weapp，不改；H5 已隐藏 .taro-tabbar__tabbar，各 tab 页已在 H5 下自行渲染 FloatingDock，改为渲染 ResponsiveNav，跳转仍用 Taro.switchTab，hash 路由与页面清单不变。
  5. 悬停一律放在 @media (hover: hover) and (pointer: fine) 内，避免触屏 iPad 出现粘滞 hover；焦点用 :focus-visible，鼠标点击不出外环。
  6. 不新增依赖、不改路由与接口；手机端视觉以现网为准，只有「我的」页底部新增账号区 + 备案号。
